## 一、项目概述与建立过程

### 1.1 项目来源

本项目基于开源项目 [NanmiCoder/MediaCrawler](https://github.com/NanmiCoder/MediaCrawler) 二次开发，面向「小红书创作者内容批量爬取 → 飞书多维表格自动上传」这一具体业务场景。

### 1.2 建立过程概览

| 阶段 | 主要工作 |
|------|----------|
| **基础选型** | 选定 MediaCrawler 作为基础框架，利用其 Playwright 登录、小红书 API 调用、反爬策略等能力 |
| **批量能力** | 新增 `tools/batch_crawler.py`，从 Excel 读取作者列表，逐个调度爬取 |
| **Web 管理** | 新增 Dashboard、控制面板、远程扫码登录等 Web 界面 |
| **飞书集成** | 集成飞书多维表格 API，支持爬取结果自动推送（含图片/视频上传） |
| **安全与运维** | 增加密码认证、Session 保活、优雅中止、断点续爬、日志轮转等 |

### 1.3 技术架构

```
用户浏览器 (login / dashboard / control)
         ↓ HTTP / WebSocket
FastAPI 后端 (端口 9001)
         ↓
批量爬取调度器 (batch_crawler.py)
         ↓
小红书爬虫核心 (Playwright + API 客户端)
         ↓
数据存储 (JSON / Excel / 飞书)
```

- **后端**：Python 3.10+、FastAPI、Uvicorn
- **爬虫引擎**：Playwright (Chromium)
- **前端**：Vue 3 (CDN)、Tailwind CSS，无需构建
- **环境**：Conda (uvenv)，部署环境用 Conda 替代原版 uv

## 二、功能清单

### 2.1 核心功能

| 功能 | 说明 |
|------|------|
| **批量作者爬取** | 从 Excel 读取作者列表，逐个爬取笔记，支持断点续爬、历史复用 |
| **爬取模式** | 全量 / 日期范围 / 增量更新，可在配置中切换 |
| **数据过滤** | 按互动量阈值、日期范围过滤 |
| **本地导出** | Excel、JSON、CSV |
| **飞书多维表格** | 自动创建多维表格，批量写入数据，支持图片/视频附件 |
| **图片补全** | 爬取时下载图片到本地，飞书推送时优先从本地上传（解决 URL 过期 403） |

### 2.2 Web 管理界面

| 页面 | 路径 | 功能 |
|------|------|------|
| **远程扫码登录** | `/login` | WebSocket 远程浏览器，在无图形界面服务器上完成小红书扫码 |
| **控制面板** | `/control` | 配置、启停、实时日志、文件管理 |
| **数据仪表盘** | `/dashboard` | 登录管理、爬取设置、批量爬取、飞书配置、日志/文件、导出 |
| **终端日志** | `/shell` | 网页版终端，可执行命令 |

### 2.3 运维与安全

| 功能 | 说明 |
|------|------|
| **密码认证** | 所有 API 需 Bearer Token，密码来自环境变量 `MC_DASHBOARD_PWD` |
| **Session 保活** | `session_keeper.py` 每 3 小时刷新 Cookie，防止长时间爬取时过期 |
| **优雅中止** | SIGTERM/SIGINT 时保存当前作者部分数据，标记 partial，下次补爬 |
| **失败重试** | 支持清除失败记录，重新爬取 |
| **日志轮转** | 按天轮转，保留 14 天 |

### 2.4 反爬策略

- 随机等待（8~23 秒，对数正态分布）
- 批次暂停（每 16~30 条暂停 30~60 秒）
- 大暂停（每 300 条暂停 4~6 分钟）
- 假动作（15% 概率搜索、滚动、鼠标移动）
- 动态调速（成功加速、限流减速、验证码超级休眠）
- 浏览器伪装（去除 WebDriver 标记、伪造指纹）

## 三、遇到的问题与解决方案

### 3.1 登录与会话

#### 问题 1：服务器无图形界面，无法扫码登录

**现象**：Linux 服务器无显示器，无法展示二维码。

**方案**：WebSocket 远程浏览器。服务器用 Playwright 打开登录页，每 300ms 截取画面通过 WebSocket 推送到用户浏览器，用户点击/输入事件回传执行。相当于简化版远程桌面。

**效果**：用户访问 `/login` 即可完成扫码、验证码、滑块等全部登录流程。

---

#### 问题 2：扫码后误报「登录成功」

**现象**：未扫码就显示登录成功。

**根因**：只检查 UI 元素（二维码是否消失），不校验 Cookie 有效性，旧 Cookie 过期但仍存在导致误判。

**方案**：改为 API 校验。通过浏览器内 JS 调用 `https://edith.xiaohongshu.com/api/sns/web/v1/user/selfinfo`，根据 HTTP 状态码和返回数据判断 Cookie 是否有效。

**效果**：只有真正登录成功才会提示。

---

#### 问题 3：二维码每秒刷新，无法扫码

**现象**：二维码不断更换，用户来不及扫。

**根因**：轮询间隔 1000ms 过短，每次轮询触发截图刷新。

**方案**：轮询改为 3000ms；增加二维码过期检测，过期时自动点击刷新；使用更精确的过期关键词匹配。

**效果**：二维码稳定显示，扫码成功率提高。

---

#### 问题 4：远程浏览器无法输入短信验证码

**现象**：键盘事件转发无法正确输入验证码。

**根因**：Playwright `keyboard.press()` 逐键发送，验证码输入框有前端校验，单键事件无法正确更新输入值。

**方案**：前端增加独立输入框和「发送」按钮，用户输入完整验证码后，后端调用 `page.keyboard.type(text)` 一次性输入。

**效果**：验证码输入正常。

---

#### 问题 5：Session 过期导致爬虫中断

**现象**：长时间爬取（数小时）后，`web_session` 过期，后续请求全部失败。

**方案**：开发 `tools/session_keeper.py`，每 3 小时用 Playwright 打开小红书页面触发 Cookie 刷新，保存到共享文件；爬虫运行时自动跳过保活（SingletonLock 检测）。

**效果**：长时间爬取不再因 Session 过期中断。

---

### 3.2 爬虫与数据

#### 问题 6：`_failed` 类型错误导致崩溃

**现象**：`TypeError: list indices must be integers or slices, not str`，`mark_completed()` 时崩溃。

**根因**：进度文件中的 `failed` 期望为 `dict`，但被写成 `list`（手动编辑或旧版写入）。

**方案**：加载时检测类型，`list` 转为空 `dict`；保存前检查；操作前防御性校验。

**效果**：进度文件格式异常时不再崩溃。

---

#### 问题 7：日期过滤不生效，继续爬取超期笔记

**现象**：设置 2025-01-01 之后，仍爬取大量 2024 年旧帖。

**根因**：日期检查在内层逐条执行，停止标志无法传到外层分页循环；且单批 30 条内有一两条旧帖就停止太敏感（置顶帖干扰）。

**方案**：改为批次级停止。连续 2 个批次（每批 30 条）都包含超期笔记时停止，容忍单批内少量置顶旧帖。

**效果**：日期过滤正确，无效翻页减少。

---

#### 问题 8：中断导致数据丢失

**现象**：爬第 10 个作者时已爬 265 条，Ctrl+C 后数据全部丢失。

**根因**：只有完整爬完一个作者才写入任务目录，中途中断不保存。

**方案**：注册 SIGTERM/SIGINT 处理器；收到信号时收集当前作者部分数据 → 写入任务目录 → 标记 partial → 退出；下次启动时 partial 作者重新爬取，旧数据合并。

**效果**：中断后不再丢数据，可无缝恢复。

---

### 3.3 部署与运维

#### 问题 9：`uv not found`

**现象**：点击「开始爬取」后报 `uv: command not found`。

**根因**：原版使用 `uv run`，部署环境用 Conda（uvenv）。

**方案**：将 `uv run` 替换为 `conda run --no-capture-output -n uvenv python -u`，涉及 `api/main.py`、`api/routers/dashboard.py`、`api/routers/control.py`、`api/services/crawler_manager.py`。

**效果**：命令在 Conda 环境下正常执行。

---

#### 问题 10：API 返回中文乱码

**现象**：`{"output": "鍛戒护琛屽叆鍙"}` 而非中文。

**根因**：FastAPI 默认 JSON 未显式设置 `charset=utf-8`，浏览器有时按 GBK 解码。

**方案**：自定义 `UTF8JSONResponse`，`media_type = "application/json; charset=utf-8"`；subprocess 调用中设置 `PYTHONIOENCODING=utf-8`。

**效果**：中文正常显示。

---

#### 问题 11：Dashboard 只爬了 5 个作者

**现象**：Excel 有 18 个作者，实际只爬 5 个。

**根因**：前端 `batchForm.limit` 默认值为 5。

**方案**：将 `limit` 默认值改为 0（0 表示不限制）。

**效果**：默认爬取全部作者。

---

#### 问题 12：9 个作者失败后无法重爬

**现象**：Session 过期导致 9 个作者失败，失败记录阻止重试。

**方案**：新增 `POST /batch/progress/clear-failed` 接口和「清除失败记录」按钮；增加任务状态面板显示 completed/failed/partial/remaining。

**效果**：可清除失败记录后重试。

---

#### 问题 13：日志窗口不刷新

**现象**：半小时无新日志输出。

**根因**：5 秒轮询 + API 端竞态，经常返回空或重复内容。

**方案**：用 WebSocket 替代轮询；后端每行日志即时广播；前端实时渲染。

**效果**：日志实时显示。

---

#### 问题 14：公网暴露被机器人扫描

**现象**：日志出现大量非预期的 GET 请求（Censys、AWS 等扫描器）。

**方案**：增加密码认证中间件；`/api/auth/login` 验证密码，返回 Token；API 请求需 Bearer Token；密码从 `MC_DASHBOARD_PWD` 读取。

**效果**：未登录无法访问受保护接口。

---

#### 问题 15：SSH 断开后爬虫终止

**现象**：关闭终端后爬虫进程退出。

**方案**：使用 tmux。`tmux new-session -d -s crawler '...'` 后台启动；`tmux attach -t crawler` 查看。

**效果**：SSH 断开后爬虫继续运行。

---

#### 问题 16：日志文件无限增长

**现象**：长时间运行后 `logs/crawler.log` 占用大量磁盘。

**方案**：配置 `TimedRotatingFileHandler`，按天轮转，`backupCount=14`。

**效果**：日志控制在合理大小。

---

### 3.4 数据质量

#### 问题 17：图片 URL 403 Forbidden

**现象**：飞书推送时图片链接过期，上传失败。

**根因**：小红书 CDN 链接带有时效签名，事后下载会 403。

**方案**：`image_mode=image` 时爬取阶段同步下载到 `data/xhs/images/{note_id}/`；飞书推送优先从本地文件上传，URL 作为回退；CDN 请求加 `Referer: https://www.xiaohongshu.com/`。

**效果**：图片上传成功率显著提高。

---

#### 问题 18：部分笔记互动量为空字符串

**现象**：`liked_count` 等为空字符串。

**根因**：小红书 API 对 0 赞等低互动笔记不返回数值。

**方案**：导出和过滤时 `int(x or 0)`，空字符串视为 0。

**效果**：互动量计算正确。

## 四、经验与教训

1. **防御性编程**：对 JSON、API 返回等外部数据不信任类型，加载时做类型检查和转换。
2. **断点续爬必须**：长任务随时可能因网络、风控、Bug 中断，必须有可靠进度持久化。
3. **反爬需调参**：对数正态分布等策略需根据实际风控情况调整。
4. **WebSocket 优于轮询**：实时反馈场景优先用 WebSocket。
5. **优雅中止**：长任务要支持「随时中断、尽量保留数据」。
6. **公网必认证**：即使内部工具，暴露公网后很快会被扫描，必须加认证。
7. **环境适配**：部署前确认实际 Python 环境（uv / conda / venv），避免硬编码。
8. **中文编码**：涉及中文的 Web 服务，显式设置 `charset=utf-8`。
9. **分层架构**：调度层、爬虫层、API 层、存储层分离，便于排查和修改。

## 六、部署说明

### 6.1 从零部署（完整步骤）

#### 步骤 1：系统与环境

```bash
# 安装 Miniconda（如已有可跳过）
wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
bash Miniconda3-latest-Linux-x86_64.sh

# 创建环境
conda create -n uvenv python=3.10 -y
conda activate uvenv
```

#### 步骤 2：克隆代码

```bash
# 若从自有仓库
git clone https://你的仓库地址/MediaCrawler.git
cd MediaCrawler

# 或从原版 fork
git clone https://github.com/NanmiCoder/MediaCrawler.git
cd MediaCrawler
```

#### 步骤 3：安装依赖

```bash
conda activate uvenv

pip install -r requirements.txt

# Playwright 浏览器
playwright install chromium
playwright install-deps
```

#### 步骤 4：准备 Excel 作者列表

将 `redbookaccontidandresult.xlsx` 放在项目根目录，包含「小红书链接」列，格式示例：

```
https://www.xiaohongshu.com/user/profile/62b114a100000000190287f0?xsec_token=xxx
```

链接需带 `xsec_token`，可从浏览器地址栏复制。

#### 步骤 5：配置文件

`config/anti_crawl_config.json` 中设置：

```json
{
  "batch_crawl": {
    "excel_path": "redbookaccontidandresult.xlsx",
    "task_id": "task_20260226",
    "crawl_mode": "full",
    "max_notes_per_creator": 3000,
    "min_interaction": 50,
    "resume": true
  }
}
```

首次登录建议通过 Web 扫码完成，无需在 `base_config.py` 中预先填 Cookie。

#### 步骤 6：设置管理密码

```bash
export MC_DASHBOARD_PWD="你的复杂密码"
# 建议写入 ~/.bashrc 持久化
echo 'export MC_DASHBOARD_PWD="你的复杂密码"' >> ~/.bashrc
source ~/.bashrc
```

#### 步骤 7：启动 API 服务

```bash
cd /data/vonjan/program/MediaCrawler  # 改为你的项目路径

MC_DASHBOARD_PWD="你的密码" nohup conda run --no-capture-output -n uvenv \
  python -m uvicorn api.main:app --host 0.0.0.0 --port 9001 \
  > api.log 2>&1 &

echo $!  # 记录 PID
```

#### 步骤 8：验证

- 浏览器访问 `http://服务器IP:9001/dashboard`
- 输入密码登录
- 在「登录管理」完成小红书扫码
- 在「批量爬取」确认作者列表，可先 `--limit 2` 测试

### 6.2 域名与反向代理（可选）

若使用 Nginx + HTTPS：

```nginx
server {
    listen 443 ssl;
    server_name crawler.example.com;

    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:9001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

### 6.3 常用运维命令

```bash
# 停止 API

# 后台运行爬虫（tmux）

tmux attach -t crawler

# Session 保活（可选，长时间爬取建议开启）
conda run -n uvenv python -m tools.session_keeper &
```
