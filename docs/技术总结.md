## 一、项目概述

### 1.1 项目目标

从小红书平台批量采集指定博主（作者）的公开笔记数据，包括图文内容、视频、互动数据等结构化信息，按照指定日期范围和互动量进行过滤，最终导出为 Excel 文件并自动同步到飞书多维表格，供运营团队进行竞品分析和内容研究。

| HTML 管理页面 | 9 个 |
| 配置文件 | 2 个 |

## 三、核心模块详解

### 3.1 批量爬取调度器 (`tools/batch_crawler.py`, 2550 行)

这是整个系统的主入口和调度中心。

**完整执行流程：**

```
1. 初始化
   ├─ 读取 anti_crawl_config.json 配置
   ├─ 将配置注入到全局 config 模块
   ├─ 从 Excel 读取作者列表 (名称 + 主页URL)
   └─ 加载批量任务进度 (batch_progress_{task_id}.json)

2. 遍历作者列表
   ├─ 已完成 → 跳过
   ├─ 历史数据可复用 → 直接标记完成
   └─ 需要爬取 → 进入爬取流程
       ├─ 创建 XiaoHongShuCrawler 实例
       ├─ 设置 config.XHS_CREATOR_ID_LIST = [当前作者URL]
       ├─ 调用 crawler.start() 开始爬取
       ├─ 收集爬取结果到 task 目录
       ├─ 成功 → progress.mark_completed()
       └─ 失败 → progress.mark_failed() + 记录错误

3. 数据校验
   ├─ 检查每个作者的 user_id 是否匹配
   ├─ 检查是否有空数据或异常数据
   └─ 校验失败 → 自动补爬

4. 数据聚合
   ├─ 合并所有作者的 JSON 数据
   ├─ 按 note_id 去重
   ├─ 按日期范围过滤 (如 2025-01-01 ~ 2026-02-10)
   └─ 按互动量过滤 (点赞+收藏+评论 ≥ 阈值)

5. 图片补全 (若启用飞书图片模式)
   ├─ 扫描哪些笔记缺少本地图片
   ├─ 从小红书 CDN 下载缺失图片
   └─ 失败的进行第二轮补录

6. 本地导出
   ├─ Excel: 每个作者一个工作表
   ├─ CSV: 单文件
   └─ JSON: 单文件

7. 飞书推送 (可选)
   ├─ 创建飞书多维表格
   ├─ 每个作者创建一张数据表
   ├─ 定义字段 (文本/链接/附件/数字)
   ├─ 上传图片和视频为飞书附件
   ├─ 批量写入数据记录 (每批100条)
   └─ 创建"热门作品"筛选视图
```

**关键类：**

- `BatchProgress` — 进度管理，支持断点续爬、失败重试
- `ExcelCreatorReader` — Excel 解析，自动识别列名
- `collect_crawled_data()` — 数据收集和去重
- `format_note_for_export()` — 字段映射和格式化
- `push_to_feishu()` — 飞书多维表格推送

**命令行参数：**

```bash
python -m tools.batch_crawler                    # 默认运行
python -m tools.batch_crawler --skip-feishu      # 跳过飞书推送
python -m tools.batch_crawler --limit 5          # 只爬前5个作者
python -m tools.batch_crawler --patch-only       # 只补图不爬取
python -m tools.batch_crawler --force-recrawl    # 强制全部重爬
python -m tools.batch_crawler --export-only      # 只导出不爬取
```

### 3.2 小红书爬虫核心 (`media_platform/xhs/core.py`, 1054 行)

**技术原理：**

小红书的 Web API 有严格的请求签名校验机制（`X-S`、`X-T`、`X-S-Common` 等 Header），这些签名由前端 JavaScript 在浏览器环境中动态计算，无法用纯 HTTP 请求模拟。

系统采用 **Playwright 无头浏览器** 方案：

1. 启动 Chromium 浏览器（headless 模式，无需显示器）
2. 加载小红书页面，浏览器自动执行小红书的 JS 代码
3. 注入自定义 JS 脚本，调用小红书内置的签名函数
4. 拿到合法签名后，构造 API 请求获取数据

**单个作者的爬取流程：**

```
Phase 1: 获取作品列表 + 详情
  ├─ 调用 get_all_notes_by_creator() 分页获取列表
  │   └─ 每页 30 条，通过 cursor 翻页
  ├─ 对每条笔记调用 get_note_by_id() 获取完整详情
  ├─ 调用 get_notice_media() 下载图片和视频
  ├─ 日期检测: 连续 2 个批次(30条/批)包含超期笔记 → 停止
  └─ 每 10 条保存一次断点进度

Phase 2: 补爬失败的详情
  ├─ 对 Phase 1 中失败的笔记重试
  └─ 等待 60 秒冷却后重试

Phase 3: 评论获取 (可选)
  ├─ 并行模式: 在 Phase 1 中边爬详情边爬评论
  └─ 顺序模式: Phase 1 完成后统一获取评论
```

**登录优先级：**

```
1. Playwright 持久化浏览器目录 (browser_data/xhs_user_data_dir)
2. 共享 Cookie 文件 (data/cookies/xhs_cookies.json)
3. 配置文件中的 Cookie
4. QR 码扫码登录
```

### 3.3 API 客户端 (`media_platform/xhs/client.py`, 776 行)

**调用的小红书内部 API：**

| API 端点 | HTTP 方法 | 功能 | 频率 |
|----------|----------|------|------|
| `/api/sns/web/v1/user_posted` | GET | 获取作者发布的笔记列表 | 每页1次 |
| `/api/sns/web/v1/feed` | POST | 获取单条笔记完整详情 | 每条1次 |
| `/api/sns/web/v2/comment/page` | GET | 获取笔记一级评论 | 每页1次 |
| `/api/sns/web/v2/comment/sub/page` | GET | 获取二级评论（回复） | 每页1次 |
| `/api/sns/web/v1/search/notes` | POST | 关键词搜索笔记 | 搜索模式 |
| `/user/profile/{user_id}` | GET | 获取作者主页信息 | 每作者1次 |

**请求签名机制：**

```python
# 每次 API 请求前，通过 Playwright 注入 JS 计算签名
headers = {
    "X-S":         签名值 (基于请求URL和Cookie计算),
    "X-T":         时间戳,
    "X-S-Common":  公共签名参数,
    "X-B3-Traceid": 追踪ID,
}
# 签名依赖浏览器环境中的 a1 Cookie 和小红书内置的加密函数
```

**错误处理：**

| 错误类型 | 处理策略 |
|----------|---------|
| HTTP 408/429/500/502/503/504 | 指数退避重试（2s→4s→8s→...120s） |
| HTTP 401/403 | 不可恢复，立即停止 |
| 风控限流 (300012/300013) | 长时间等待（240s→480s→900s+） |
| 连续 3 次 API 异常 | 停止当前作者 |
| 网络超时 | 等待后重试 |

### 3.4 反爬策略引擎 (`tools/anti_crawl_utils.py`, 451 行)

小红书有完善的反爬虫系统，包括请求频率检测、行为模式分析、浏览器指纹识别等。系统采用**七层防御**：

#### 第一层：随机等待

```python
# 每次 API 请求之间的等待时间
分布类型: 对数正态分布 (lognormal)  # 更接近真人行为
最小等待: 8.0 秒
最大等待: 23.0 秒
# 对数正态分布的特点：大部分等待时间集中在较短区间，偶尔出现较长等待
```

#### 第二层：批次暂停

```python
# 每爬取 N 条后暂停（N 本身也是随机的）
触发间隔: 随机 16~30 条
暂停时长: 30~60 秒
# 模拟用户"看累了休息一下"的行为
```

#### 第三层：大暂停

```python
# 长时间爬取后的大休息
触发间隔: 每 300 条
暂停时长: 240~360 秒 (4~6分钟)
# 模拟用户"离开去做其他事"的行为
```

#### 第四层：假动作

```python
# 15% 的概率执行与爬取无关的操作
动作类型:
  - 搜索随机关键词 ("美食"、"旅行"、"穿搭"...)
  - 随机滚动页面
  - 移动鼠标
  - 点击用户头像
  - 在搜索框输入后删除
等待时长: 2~5 秒
# 让行为模式不那么"机械"
```

#### 第五层：动态调速

```python
# 根据爬取结果动态调整速度
连续成功 10 次 → 速度乘以 0.8 (加速)
遇到限流        → 速度乘以 2.0 (减速)
遇到验证码      → 超级休眠 300~600 秒 (5~10分钟)
```

#### 第六层：浏览器伪装

```python
# 注入 stealth.min.js 脚本
- 移除 navigator.webdriver 标记
- 伪造 Canvas 指纹 (每次不同)
- 伪造 WebGL 指纹
- 伪造 navigator.plugins
- 伪造 navigator.languages
# 让浏览器看起来像普通用户的 Chrome
```

#### 第七层：日期智能停止

```python
# 避免无效翻页
检测单位: 批次 (每批 30 条)
连续 2 个批次包含早于起始日期的笔记 → 停止该作者
# 处理置顶帖: 单个批次有老帖不会误触发
```

### 3.5 登录与会话管理

#### 远程扫码登录 (`api/routers/login.py`, 927 行)

**问题**：服务器是纯命令行环境，无法直接显示二维码让用户扫码。

**解决方案**：WebSocket 远程浏览器

```
用户浏览器                  服务器
    │                         │
    │  ①访问 /login           │
    │ ──────────────────────> │
    │                         │
    │  ②WebSocket 连接        │  ③启动 Playwright 无头浏览器
    │ <────────────────────── │     打开小红书登录页
    │                         │
    │  ④每300ms发送JPEG截图    │  ⑤浏览器内存中渲染页面
    │ <═══════════════════════│     截取页面为JPEG图片
    │                         │
    │  ⑥Canvas渲染画面         │
    │  用户看到登录二维码       │
    │                         │
    │  ⑦鼠标/键盘事件回传      │  ⑧Playwright 执行操作
    │ ═══════════════════════>│     (点击/输入/滑动)
    │                         │
    │  ⑨检测到登录成功         │  ⑩保存 Cookie 到文件
    │ <──────────────────────│     data/cookies/xhs_cookies.json
```

**技术细节：**
- 画面传输：JPEG 格式，quality=40，分辨率 1024x680，帧率 ~3 FPS
- 事件处理：每帧最多处理 20 个积压事件
- 登录检测：通过浏览器内 JS `fetch` 调用小红书用户信息 API 验证
- 支持：二维码扫码、短信验证码输入、滑块验证

#### Session 保活 (`tools/session_keeper.py`, 304 行)

```python
# 定期刷新 Cookie 防止过期
刷新间隔: 3 小时
工作方式: 
  1. 用同一浏览器数据目录打开小红书
  2. 加载页面触发 Cookie 刷新
  3. 保存更新后的 Cookie 到文件
冲突保护: 爬虫运行时自动跳过 (SingletonLock)
```

## 六、安全与合规

1. **请求频率控制**：多层随机等待策略，单个请求间隔 8~23 秒，远低于手动浏览速度
2. **数据范围**：仅采集公开发布的笔记内容，不涉及私信、私密笔记等
3. **遵守 robots.txt**：参照目标平台规则
4. **Cookie 安全**：登录凭证加密存储在服务器本地，不外传
5. **反爬尊重**：遇到风控限流主动退避，不暴力突破
