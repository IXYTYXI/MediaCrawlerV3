# MediaCrawler 控制面板使用手册

> 控制面板用于：配置爬虫参数、启动/停止爬虫、查看实时日志、管理数据文件。
> 访问地址：`https://你的域名/control`（例如 `https://crawler.ooioo.us.ci/control`）

---

## 一、首次使用前的准备

### 1.1 登录

打开控制面板后，会看到登录界面。输入**管理密码**（与 Dashboard 相同，由部署时设置的 `MC_DASHBOARD_PWD` 决定）。

- 若密码正确，进入主界面
- 若提示密码错误，请向管理员确认密码

### 1.2 完成小红书登录（必须）

在开始爬取前，必须先完成小红书的登录（保存 Cookie/Session）。有两种方式：

**方式 A：远程登录页面**

1. 点击顶部导航「**远程登录**」
2. 在打开的扫码登录页面中，用小红书 App 扫描二维码
3. 扫码成功后，等待页面提示「登录成功」
4. 返回控制面板

**方式 B：在 Dashboard 中扫码**

1. 点击顶部导航「**数据仪表盘**」
2. 在「登录管理」中点击「打开扫码登录」
3. 完成扫码后返回控制面板

> 重要：若未完成扫码登录就启动爬虫，会提示 Session 失效，爬取失败。

## 二、配置爬虫参数

点击「**配置管理**」标签，按需修改以下配置。

### 2.1 批量爬虫（核心配置）

| 配置项 | 说明 | 推荐值 |
|-------|------|--------|
| **任务 ID** | 区分不同爬取任务，同一任务可断点续爬 | 如 `task_20260226`，下次全量可改新 ID |
| **Excel 文件路径** | 作者列表文件路径 | 如 `redbookaccontidandresult.xlsx`，需放在项目目录下 |
| **爬取模式** | 全量/日期范围/增量更新 | 首次用「全量爬取」，之后可选「增量更新」 |
| **每作者最大笔记数** | 每个作者最多爬多少条 | 建议 2000~3000 |
| **开始日期 / 结束日期** | 仅在「日期范围」模式生效 | 如 2025-01-01 ~ 2026-02-26 |
| **作者间等待 (秒)** | 每爬完一个作者后等待多久 | 建议 10~30，避免被封 |
| **最小互动量过滤** | 低于此值的笔记不保存 | 0=不过滤，50=过滤低互动 |
| **导出格式** | 导出文件格式 | Excel / JSON / CSV |
| **导出目录** | 导出文件保存位置 | 如 `data/export` |
| **断点续爬** | 是否跳过已完成的作者 | 开启：下次可接着爬；关闭：每次都从头 |
| **复用历史数据** | 是否复用之前爬过的数据 | 开启可加快；关闭则全部重爬 |
| **每次全量** | 勾选后本次运行会重置进度、全部重爬 | 需要「完整数据」时勾选 |

**爬取模式说明：**

- **全量爬取**：每个作者从头到尾爬，数据最完整
- **日期范围**：只爬指定日期区间的笔记（需填开始/结束日期）
- **增量更新**：对已完成的作者，只爬上次之后的新内容，适合定期补新

### 2.2 保存配置

修改完成后，点击页面上的「**保存配置**」按钮，确保配置写入配置文件。

## 三、启动与停止爬虫

### 3.1 启动爬虫

1. 切换到「**启动控制**」标签
2. 确认状态为「未启动」
3. 点击「**启动**」按钮
4. 等待几秒，状态变为「运行中」，并显示 PID 和运行时间

### 3.2 查看实时日志

1. 切换到「**实时日志**」标签
2. 日志会实时滚动显示
3. 可点击「自动滚动: 开/关」控制是否自动跟随
4. 点击「清空」可清空当前显示（不影响实际爬取）

### 3.3 停止爬虫

在「启动控制」标签中，点击「**停止**」按钮。爬虫会先保存当前进度，再退出（通常需几秒到十几秒）。

---

## 四、查看与管理数据

### 4.1 文件管理

1. 切换到「**文件管理**」标签
2. 点击「刷新」可加载最新数据文件列表
3. 点击某个 JSON 文件旁的「查看」可预览内容
4. 支持分页浏览，可查看笔记条数、字段等

### 4.2 导出结果

- 爬取完成后，数据会保存到 `data/xhs/json/任务ID/` 目录
- 若需导出为 Excel，可使用 Dashboard 的「导出数据」或命令行 `--export-only`

## 六、常见问题

### Q1：启动后状态一直是「未启动」？

- 可能爬虫由命令行或其他方式启动，刷新状态或点击「刷新」再看
- 若仍异常，检查 API 服务是否正常运行

### Q2：日志显示「Session 失效」？

- 需要先完成小红书扫码登录（见 1.2）
- 若已登录仍失效，可能是 Cookie 过期，请重新扫码

### Q3：想「全部重爬」怎么做？

- 在配置中勾选「每次全量」，保存后启动；或
- 在命令行运行 `python -m tools.batch_crawler --force-recrawl`

### Q4：爬取中断后如何继续？

- 保持「断点续爬」开启，直接再次点击「启动」即可
- 已完成的作者会被跳过，从未完成的作者继续

---

## 七、预期结果

- **爬取中**：实时日志有输出，状态显示「运行中」
- **爬取完成**：状态变为「已停止」，数据在 `data/xhs/json/任务ID/` 下
- **导出**：可在「文件管理」中查看 JSON，或使用 Dashboard/命令行导出为 Excel

按上述步骤操作，即可完成配置、启动、查看日志和结果。
